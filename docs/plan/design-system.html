One modern theme for the whole app

The React page still wears the old page's stylesheet, copied as is (488 lines). Each screen sized and spaced things its own way. This replaces it with one theme: a small set of tokens and about 15 shared pieces (buttons, fields, dialogs, rows). Every screen is built only from those, so it looks the same everywhere, in light and dark, on the Mac and on phones.

The look

Modern and quiet, from the brand you already have: ink and white, one Switch red, the system font (no outside requests). Red is kept for the one main action and the brand. Hierarchy comes from weight and spacing, not boxes. Dialogs float on a soft shadow, and choices are segmented controls, not rows of radio buttons. It follows the Mac's light or dark setting.

Fewer words: the rules

  • A hint is one line at most. No explanation paragraphs under choices.
  • Empty sections are hidden, not explained.
  • No internal names on screen (ids like @divit-learning, model names, request counts), except where you've set up your own OpenRouter (below).
  • Plain words, American spelling, as now.

Already done in this round (in the React page, tests updated): the long privacy paragraphs in Bot settings, New bot and Make private are gone. The empty Reports section is hidden. The Free models pill is gone. The @name under each bot is now what it's for.

Model names and cost under answers

The line under an answer (· nemotron-3.5-lightning:free · 1 question · $0.00) shows only when the home uses its own OpenRouter account. A home set up through oxbot's cloud (you provision the key at sign-in; usage capped, about $2) never shows model names, cost, Kind of job or a model list, because the app picks the models.

Today every home is on its own OpenRouter account (the cloud setup isn't built yet), so the line stays until the cloud setup ships. I'll add the two setups to the accounts and backup plan. If you'd rather hide the line for everyone now, say so.

How it's built

  1. Theme: theme/tokens.css (color by role, light and dark, plus spacing, corners, type, shadow, motion) replaces tokens.css. The brand page uses the same values.
  2. Pieces: components/ui/, each with its own small CSS file, built only from tokens.
  3. Screens moved one at a time: Sidebar, Chat, Bot settings, New bot, Settings tabs, Cards, Welcome. Each drops its part of legacy.css. At the end legacy.css is deleted.
  4. Guard: check-ui.sh fails on raw colors, pixel font sizes or inline styles outside the theme, so it stays consistent.
  5. A page of every piece (owner's dev tools only) for review in both themes.
  6. Phones: the same pieces with 44-pt touch targets.
  7. Tests: the end-to-end suite must pass. The new screenshots become the reference set after you approve them.

Decisions for you

  2. Density: roomy (recommended for phones and a home audience), or compact like today?
