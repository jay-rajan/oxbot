oxbot · Step 6 design · draft for OK · Nov 4, 2026

oxbot on Codex: a household AI you budget, that keeps your data home

Replaces the two-engine plan (Claude + OpenRouter). OpenRouter only; Codex CLI runs the agent loop; oxbot keeps the gate, page tools, a model relay, budgets, kid profiles and the UI. Sources: the Codex study (claude.ai/artifact/3CAfrb1neeeiioeva79x4U), the 12-task benchmark (claude.ai/artifact/RA9KdSqGMEuKCWTcuqxLAj), OpenRouter's terms (Aug 31, 2026), and the draft docs/legal/TERMS.md and PRIVACY.md.

Positioning

Three controls the household keeps

CostThe household sets how much AI to spend, in dollars, per person and per bot. Free models first; paid only if allowed.
DataYou're not the product. Sign-ins, history, files and scripts stay on the Mac. What a task sends out is stripped of anything that identifies you, and you can see it.
ModelPick any model on OpenRouter, or a local one, per bot. The loop is open source and model-neutral.
Decisions in this design
  • OpenRouter only. Claude Code is removed from the product and kept only as a private benchmark yardstick.
  • Codex CLI (Apache-2.0, pinned version) is the loop, run as codex app-server, one process per person.
  • Coding is allowed, but never on its own: the first script in a task needs a yes, scripts run with no network inside the bot's folder, and only their output goes to the model.
  • Kids make and run bots in kid profiles; the parent approves anything risky.

Flows

Three tasks, step by step

A · "Find 3 well-reviewed books on amazon.ca"

  1. Hub starts a turn on the person's Codex process with the bot's instructions (baseInstructions, written by oxbot, not Codex's coding prompt).
  2. Codex calls browser_navigate → item/tool/call → gate allows (a GET) → chrome-devtools-mcp. The snapshot is stored whole; Codex gets the page map, marked untrusted.
  3. Codex calls extract_rows / query_rows; Rust filters and counts.
  4. Each model request goes Codex → relay: budget ok → privacy level picks providers → "Hello, Jay" on the page becomes "Hello, [NAME_1]" → IDs stripped → OpenRouter. The outgoing text is saved for "What was sent".
  5. The final answer comes back with [NAME_1] restored locally; the numbers check runs; the chat shows the answer and the cost.

B · "Here's my bank CSV; how much did we spend on groceries per month?"

  1. The file lands in the bot's folder (upload card, as today).
  2. Codex wants to run python3 summarize.py. The first script in a task sends commandExecution/requestApproval → card: "This task needs a small script. It runs on this Mac, reads only this bot's folder and can't use the internet. Allow scripts for this task?" Allow for this task · Show the script · No.
  3. The script runs in Codex's Seatbelt sandbox: reads the bot folder (and system Python), writes only there, no network (loopback blocked too, so it can't reach Chrome or the relay).
  4. Only the script's printed output goes to the model, through the relay's PII removal. The CSV itself never leaves.
  5. Bots have a Coding setting: Off (no shell at all), Ask (default), or Allowed for this bot (admin only). Kid profiles: Ask, and the parent answers.

C · A kid asks a bot to "sign me up for this game site"

  1. The site isn't on the parent's allowed list → the card goes to the parent's devices, not the kid's.
  2. Signing up is a change → parent card again; kid profiles never get Always allow and can't sign in themselves.
  3. The kid sees "Waiting for a parent"; the parent sees the task, the page and why it was flagged.

Data

New tables and what leaves

  • budgets: household, person, bot; dollars per month and requests per day; reset times. spend rolls up from model_calls.
  • relay_log ("What was sent"): per request the outgoing text after PII removal, model, provider, tokens, cost. Owner and the person only; kept 30 days by default.
  • pii_map: placeholder ↔ real value, per task, never leaves the Mac, deleted when the task ends.
  • kid_profiles: parent, allowed sites, hours, coding setting; approvals gain an approver.
  • coding_consents: per task, who allowed scripts and when.
  • Codex's own files (rollouts, state DB) live in each person's CODEX_HOME inside oxbot's data folder; oxbot's retention sweep covers them.

Open

For you to decide

  • Cloud models for kids need OpenRouter's written OK (their §2: 18+). Until then, kid bots are Local only, so step 6 waits on step 8 unless OpenRouter says yes.
  • Keep oxbot's own loop as a fallback after the spike, or retire it? Retiring halves the code to maintain; keeping it guards against Codex changing its protocol.
  • Which Python scripts use: the Mac's own python3 (may be missing), or ship one with oxbot (bigger app).
