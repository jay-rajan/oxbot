Set up the home's AI from inside oxbot, step by step

You asked whether the app can guide people through OpenRouter. Today it's one button buried in Settings → AI models. This page moves it into the welcome screen as a short guide that a non-technical parent can finish in a few minutes, and that checks each step itself.

1 · What's there today

The pieces already work; the guidance is missing

  • Sign in without keys: "Sign in with OpenRouter" opens the browser, the person approves, and the key goes straight into the Keychain. Nobody copies anything.
  • oxbot can read the account's state: free questions used today (of 50 or 1,000), whether credit was ever bought, spending today and the limit.
  • Owner confirms 18+ and OpenRouter's terms on the welcome screen.
  • Missing: nothing explains what OpenRouter is, that a new account can be made during sign-in, why adding $10 once matters, or what to do next. A bot simply fails with "The home's AI account isn't connected yet."

4 · How it's built

A small state machine on the home computer

flowchart LR
  A["not_connected"] -->|"sign-in returns (Keychain)"| B["connected_free
50/day"]
  B -->|"key shows credit bought"| C["credit_added
1,000/day"]
  B -->|"Skip"| D["paid_choice"]
  C --> D
  D -->|"Off / $1 / $5"| E["ready"]
  E -->|"key revoked"| A
  • Setup state is derived, not stored: from the key's state (signed in, free tier or not) plus one saved flag per screen the owner skipped. So it fixes itself if the account changes outside oxbot.
  • Checking by itself: while screens 3 or 4 are open, the home computer re-reads the key every 5 s (screen 3 already gets the sign-in callback; screen 4 polls the key's free-tier flag) and moves on. No "I've done it" button needed, but Refresh stays as a fallback.
  • Links: oxbot opens only fixed openrouter.ai pages (sign-in, credits) in the person's normal browser. It never fills forms there and never handles card details or passwords.
  • Home computer only: setup and spending choices stay farm-only (as today). Devices see the "Ask Jay…" line.
  • Words: "OpenRouter" is named (it's their account). Never Codex or relay. "Free questions" not "requests"; "AI spending" not "cap".
  • Tests: unit tests for the derived state; e2e with the fake OpenRouter (already serves the sign-in page) plus a free-tier switch and a "credit bought" switch: guide → sign in → 50/day screen → credit → 1,000/day → paid choice → done. Nudges at 80% and 100%.
5 · To check before code

Two things to verify

  1. Sign-up during sign-in: does OpenRouter's authorize page let a brand-new person create an account and then return to oxbot in one go? I'll test it in a fresh browser profile without signing up (no account made). If it doesn't, screen 2 gets a "Create account" link first.
  2. Card fee wording: OpenRouter charges a small fee on card top-ups; the guide will say "plus OpenRouter's card fee" with the number read from their page at build time, not hard-coded.
Later, with an AI model on this computer: screen 1 gains a first choice, "Use AI on this computer (private, free)", when the Mac is strong enough; then OpenRouter becomes optional, for web tasks. That's a separate design.
