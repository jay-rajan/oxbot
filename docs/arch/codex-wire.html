Who holds what

Codex holds the conversation and runs the loop. oxbot holds everything else: who you are, the tools, permissions, the model choice and the clock. They meet at two boundaries: stdio for control, and HTTP for model requests.

What the relay changes on the way out

Codex thinks it's talking to OpenAI. The relay rebuilds every body from an allow-list before it leaves the Mac, and that rebuilt body is what gets saved.

FieldWhat happens
input, instructions, stream, function toolsKept. Ids that Codex made on messages and tool outputs are removed; call_id stays
model, models, provider, max_output_tokensSet by oxbot's gateway: the bot's model, its fallbacks, privacy rules, the answer cap
tool_choice, parallel_tool_calls, reasoning, include, temperature, top_pKept only if the model accepts them
metadata, client_metadata, user, prompt_cache_key, store, previous_response_id, anything unknown; all headersRemoved. Nothing that identifies the installation, session or thread leaves
Names, emails and other personal details anywhere in the textSwapped for stand-ins ([person 1]) going out and swapped back in the stream coming in. The mapping stays on the Mac (stand-ins-<session>.json)

What the run shows

Codex is stopped in the middle of long turns bug

Three of the six turns ended with "The bot's AI helper stopped unexpectedly": at 14:49:03 (the turn had run 951 s), 15:22:09 (942 s) and 16:05:31 (932 s). Each time an approval card was open, and it was marked denied in the same second. All three are 15 minutes plus up to one minute, which matches the 15-minute idle_stop and the one-minute sweep.

Cause: the Codex supervisor has its own idle sweep (oxbot-codex/src/engine.rs:183-190, which calls Supervisor::stop_idle at supervisor.rs:222-240). It checks only last_used, and that is set when a turn starts (get, hold) and when it ends (touch, engine.rs:601). Nothing updates it during a turn, and the sweep doesn't look at users or whether a turn is running. The Hub's own sweep (hub/turns.rs:524-546) skips busy bots and pending approvals, but that check never reaches the supervisor.

Fix to consider: have stop_idle skip slots with a running turn (or with users > 0), or touch the slot on every Codex message and tool result. Add a test where a turn waits more than idle on an approval.

Each step re-sends everything cost and speed

The request grew from 37 KB to 217 KB, and input tokens from 11.6k to 54.8k per step. The provider's prompt cache absorbed it (87% of 2.34M input tokens were cached), so it cost nothing on free models. On a paid model, the uncached 311k tokens plus cached reads would still add up. Codex compacts only near model_auto_compact_token_limit, and with a 1,000,000-token window that never happened here. Large snapshots stay in the history as maps, but every small result stays forever.

The fallback model did most of the cart work slowly routing

The bot asks for nemotron-3-ultra-550b. OpenRouter answered 31 requests with the fallback nemotron-3.5-super-vl, averaging 34.7 s per step. The 37 answered by Ultra averaged 6.3 s. Every request from 14:29 to 15:06, including all of the first Walmart turn, came from the slow fallback. After that the two alternated.

A new oxbot session means a new Codex thread with no memory context

meal-plan-2 has three threads today (12:35, 13:03, 14:29), one per oxbot session. The 14:29 message ("I want 1, 2,3…") referred to the plan from the earlier thread. The model's reasoning says so: "This likely refers to a previous meal plan, but this is the first message." It rebuilt a plan and asked you to confirm.
