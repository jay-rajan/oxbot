Codex ships inside the app, one app per chip

Every bot runs on Codex. Until now oxbot used whatever Codex was installed on the Mac, so a friend without Codex 0.148.x got a dead app. Now the app carries its own Codex and always uses it. Codex is about 260 MB per chip, so there are two downloads instead of one universal one.

Downloads

before: oxbot_0.1.0_universal.dmgboth, no Codex117 MB317 MB

Checked: started in a throwaway folder with no other Codex reachable, oxbot logged "using the Codex built into the app" and found version 0.148.0 there. Both apps have the right chip type in every program, and their signatures verify.

1 · Files and functions

FileWhat changed
scripts/fetch-tools.shTakes a chip (arm64 or x64). Adds OpenAI's Codex 0.148.0 release from npm, checked against npm's sha512, plus its LICENSE and NOTICE from the same release tag (Apache-2.0). Unpacks it as shipped (program, helper, ripgrep, zsh) into tools/codex, keeping OpenAI's signatures. Node.js is now one chip, not both.
scripts/make-dmg.shbuild_one per chip: fetch tools, cargo tauri build --target, copy tools in, thin the Mac helper, sign, make_dmg. make-dmg.sh arm64 builds only the Apple chip app.

oxbot-core/src/hub/codex.rsCodexParts.built_in; pick_program: test's OXBOT_CODEX, then the app's own, then the owner's setting, then PATH.
oxbot/src/runtime.rsbuilt_in_tools_dir (shared by the browser tool and Codex), built_in_codex.
oxbot-e2e/src/main.rsThe "needs Codex" check looks in the tools folder too, in oxbot's order.
