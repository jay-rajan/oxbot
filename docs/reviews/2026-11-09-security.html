Medium and low

  • medium "Always allow" for send, post or settings changes no longer applies after a bot has read untrusted text, such as an email or web page.
  • medium "No OK needed" now covers only real cart actions (cart, bag, basket, trolley, quantity, save for later); "Add to list" asks.
  • medium The relay offers the model only oxbot's own tools and blocks calls to anything else, including Codex's patch tool, which has a sandbox bug before 0.149.
  • medium Test and dev switches (OXBOT_E2E, ?as=, tool and URL overrides) only work in debug builds; the real app ignores them. ?as= can never act as the owner.
  • medium Origin must match oxbot's exact address and port, and every route checks the Host header (against DNS rebinding).
  • medium Page security policy: connections only to oxbot itself, the page can't be framed, no form posting. The phone app's page now has its own policy.
  • medium Device pairing: wrong codes are counted per device on the Wi-Fi, so one device can't kill your code. Connections are capped per device, and the setup check is rate-limited.
  • medium The data folder is private (0700) and the database 0600. Secret files are never written through a link.
  • medium Test hooks on the page exist only in test mode.
  • medium The video helper runs in a sandbox: it reads the one video, writes only its frames, and has no network.
  • medium The Mac app is signed with the hardened runtime, which blocks code injection, and each .dmg gets a SHA-256 file.
  • low A wrong OpenRouter sign-in callback can no longer cancel yours.
  • low The release check catches every test feature, and the build is locked to Cargo.lock. Install scripts are off for npm, and the dev fallback installs the browser tool from the lockfile.

Found and fixed during testing

Combining the fixes exposed one bug in the Chrome change. oxbot switched off its private channel before asking Chrome to close, so Chrome was force-stopped after 10 seconds. That delayed sign-ins and could lose a fresh sign-in before Chrome saved it. Fixed: oxbot asks Chrome to close first. The full suite was then rerun clean.

Held up well

  • No way found to inject malicious script into the page: the Markdown renderer allows only http(s) links, was fuzzed 300,000 times, and draws as React nodes. Reports show in a sandboxed frame.
  • The OpenRouter key stays in the Keychain, never reaches logs, the page or child processes, and isn't in the public repo.
  • Scripts have no network, and Codex has no shell, a read-only sandbox, and every approval declined. The relay needs a per-process token.
  • Device pairing uses one-time codes, per-device keys, a pinned certificate, and private addresses only.
  • cargo audit and npm audit found nothing reachable in the shipped app.

Decisions and follow-ups

  1. More asking, for safety: Authorize, Enable/Disable, privacy switches and unclear form submits now ask, beyond your money-only rule. Unrecognized buttons ask too.
  2. Always-allow while browsing: for send, post and settings changes, it effectively never applies once a bot has read a page. Save, Like and Archive rules still apply.
  3. Upgrade Codex from 0.148 to current. The relay now blocks the patch tool, but the fix belongs upstream.
  4. Check on real hardware: a real make-dmg (hardened app and dictation), and the phone app with its new page policy.
  5. Release app check: it relied on test switches the real app now ignores, so it needs a small rework.
  6. Still open, lower risk: a deleted bot's files stay in the trash forever. Opening a page isn't checked, so data could leave through an address after reading private pages.
