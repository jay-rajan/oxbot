What changed

Since Step 5: Step 6. Claude is gone; every bot uses OpenRouter's models with the household's key, through oxbot's relay (Codex, the default) or oxbot's own loop. Model calls go only to OpenRouter (or, later, a local model), and to no other AI company.

  • Codex engine. oxbot-codex runs one codex app-server per bot with its own CODEX_HOME and a config oxbot writes at every start (analytics, plugins, web search, update checks, shell off). oxbot's tools reach it as dynamic tools through oxbot-loop's tool service and the hub's gate: the same approval requests, Always allow, refusals and untrusted-text marks as the loop.
  • Model relay. oxbot-relay listens on 127.0.0.1 as Codex's only model provider: it checks a per-process token, strips Codex's ids, headers and metadata, applies the bot's model, privacy and limits, forwards to OpenRouter's Responses API with the household key, meters each request and keeps what was sent for 14 days (migration 21).
  • Claude leaves. oxbot-claude, the Claude engine, the owner-only rule, Claude setup, Claude usage alerts and the Claude judge are removed. Bots that ran on Claude move to Codex once, with a line in their chat (migration 22).
  • Tests. oxbot-core::testing (feature test-bots) gives stand-in bots for hub tests; e2e reply scripts (e2e/scripts/) drive the stand-in OpenRouter on both APIs, and the suite needs codex installed.

How it grew

  1. Step 6

    Codex runs the bots on OpenRouter; Claude leaves oxbot 2026-11-04

    • New crates: oxbot-codex (finds and checks codex 0.148.x, writes each bot's CODEX_HOME config at every start, one codex app-server per bot, JSON-RPC threads and turns, oxbot's tools as dynamic tools through oxbot-loop's tool service) and oxbot-relay (127.0.0.1 Responses relay: per-process token, strips ids, headers and metadata, the bot's model, privacy and limits, meter, what was sent kept 14 days)
    • Codex's analytics, plugins, web search, update checks and shell off; any address but the relay goes to a refusing proxy; a person's own ~/.codex is never read
    • Codex is the default engine for new bots and every Herder; oxbot's own loop stays, chosen per bot through the API
    • Claude removed: the oxbot-claude crate, the Claude engine, the owner-only rule, Claude setup, Claude usage and its 5-hour/weekly alerts, the Claude judge. Usage alerts are OpenRouter's limits only
    • Upgrade: bots on engine = "claude" (or none) move to Codex at first start with one line in the chat; bot.toml rewritten once (migration 22). Chats kept; Claude sessions not resumed
    • Comparing: replays and shadows on Codex and on the loop, scoreboard measured against Codex, the owner's marks only
    • Tests: oxbot-core::testing (feature test-bots) stand-in bots; e2e reply scripts in e2e/scripts/ drive the stand-in OpenRouter (chat and Responses) and browser tool; the suite needs codex (needs = ["codex"])
  2. Step 5

    Compare engines and models per bot (#21) 2026-11-02

    • policy::trial_overlay: one practice-run overlay on the gate's verdict for both engines: cards recorded (never shown, Always-allow rules unused), refusals kept
    • Trial sandbox (oxbot-browser::trial, netguard): profile copy without history, fail-closed network guard (reads only, browser-wide too, WebSockets off by script), startup sweep
    • hub/trials.rs and hub/compare.rs: test cases, batches with an estimate and a reserve for live bots, runs under t-- keys with their own history, Claude as judge (oxbot_claude::one_shot), scoreboard, shadows; owner only, Claude only for owner-started tasks
    • Migration 18: turn_tools, test_cases, trial_batches, trial_runs, trial_events, turn_ratings
    • Page: thumbs and Test case… under replies, Compare… (scoreboard, cases, runs side by side), Shadow chip; e2e test site proves replays write nothing
  3. Step 5

    OpenRouter engine: oxbot's own loop (#18) 2026-11-02

    • New crates: oxbot-llm (OpenAI-style chat client over SSE, reqwest with rustls and ring, the platform verifier; model list, key limits, PKCE; ApiKey and KeyCell redacted) and oxbot-loop (runner, tool registry, gate check, model router, pacer, meter)
    • The loop uses Claude's tool names, and the hub's gate() answers every tool with the same policy code: cards, element kinds, taint, Always allow; passwords, scripts and files outside the bot's folder are refused. Shared policy tests for both engines
    • Browser through chrome-devtools-mcp with the official Rust MCP client (rmcp), files in the bot's folder, give_task / read_reply, save_report, ask_user
    • Free models first from the live model list (tools, 64k context or more), fallbacks on 429 and busy, 20 requests a minute household-wide, the free daily budget from the key; paid models only if the owner switches them on
    • Meter: requests, tokens and dollars per bot and person (model_calls); a daily limit per bot and per person; alerts through the usage banner
    • Private bots ask providers not to keep data (data_collection deny, zdr); if no free model qualifies oxbot says so instead of switching quietly
    • Each step saved (migration 17: loop_sessions, loop_messages, loop_turns, model_calls), so a task picks up after a restart without repeating a click
    • Sign in with OpenRouter (OAuth PKCE, state, callback on oxbot's own port); the key only in the macOS Keychain and memory, never in files, logs or the database
    • e2e: stand-in OpenRouter and browser tool reading the same scripts as the stand-in Claude; a key canary checked after every test; a restart step for tests
  4. Step 5

    Engines: engine per bot, Claude bots owner-only (#17) 2026-11-02

    • New crate oxbot-engine: Engine and Session traits, one EngineEvent stream, replies that fail closed (a dropped permission reply is a no); text::data_block moved here
    • Today's Claude path became ClaudeEngine (engine/claude.rs), an actor around the unchanged ClaudeProcess: same arguments, environment, resume and cards
    • Each bot names its engine in bot.toml (missing = claude): the main Herder stays on Claude, every other person's Herder runs on OpenRouter, new bots on OpenRouter
    • Owner-only rule in the hub (hub/engines.rs): may_task at every entry, and again once a waiting message gets its turn. Claude bots take tasks only from chains the Farm owner started: other people, their Gates, their Herders' give_task and chains someone else started are refused; others still read what the owner shares
    • ChainOrigin (who started a chain, through which Herders, taint carried) kept per turn; migration 16 (turn_origins, sessions.engine)
    • Page: engine badge, the box says "Only Jay can give this bot tasks" to others, switching a shared bot to Claude says it becomes owner-only first, Settings → Engines with the notice; a one-time list of shared Claude bots others used
  5. Step 2

    Messages with files and voice (#3) 2026-11-02

    • Attach by button, drag and drop or paste; chips with progress, plain refusals, Send with files only. POST /upload streams to work/inbox/ with the /ws auth and the bot's visibility; not on the Gate door
    • attach/: type from content (a renamed program is refused), 25 MB per file, 200 MB per video, 10 per message; Word, Excel and PowerPoint to text in Rust (zip, quick-xml, calamine), old Word, RTF and ODT with textutil, HEIC and big pictures with sips, zip-bomb guard and time limits
    • Claude gets the files by path in oxbot's own note after the person's escaped words; no system prompt change, so sessions keep their memory. Reading a file taints the session as before
    • Video: the Swift Mac helper takes evenly spaced still frames (at most 8), and the chat says Claude can't watch video
    • Voice: the same helper dictates with requiresOnDeviceRecognition, the Farm only and only where on-device recognition exists; text comes back over the WebSocket to the asking connection, in the browser and the app alike. Info.plist usage strings in the app and the helper
    • Protocol: Attachment on UserMessage and Send (serde defaults, no migration), DropUpload, OpenFile, Dictate, ServerMsg::Dictation, AppSettings.dictation

    • Store: migration 15 (limit_alerts, prefs, usage.model); check-and-record in one transaction; set_limits now updates each reported window instead of wiping the other

In the app, a bot waiting for an OK or a sign-in while the window is hidden posts its name only ("A bot" for someone else's private bot)
    • Page: an alert banner under the header, Settings → General → Notifications, usage bars amber at 50% and red at 80%

  13. Farm 2

    Gates: phones on home Wi-Fi 2026-10-31

    • Gate door (oxbot::door): TLS on port 7879 with the Farm's own self-signed certificate (rcgen, ring); phones pin its SHA-256 fingerprint from the pairing QR code
    • Pairing: one-time codes (8 characters, 10 minutes, 5 tries) shown in Settings → Gates for a chosen person; POST /pair returns a key; SQLite keeps only its hash (gates table)
    • Every other door request needs Authorization: Bearer <key> and acts as Viewer::gate(person), never the Farm
    • The door opens only on a network listed in Settings → Gates (router MAC address, gate/door.json) and while a phone is paired or a code is showing; checked every 30 s. Private-address peers only, 64 connections max, 5 s handshake, 60 s idle. mDNS _oxbot._tcp while open. OXBOT_GATE_PORT=off turns it off
    • Farm key (oxbot::secret): a random key in <data>/farm-key (0600). A local connection is the Farm only with it (/ws?k=); the app opens its window with #k=, oxbot chat and bots read the file, oxbot serve prints a link. No key, no connection (test mode ?as= aside)
    • oxbot-gate crate: the pairing link oxbot://pair?h=&f=&c=&n=, a pinned-TLS client (rustls ring + hyper http1), pair, fetch page, connect WebSocket; ChatCopy keeps the phone's own SQLite copy (latest 300 messages per bot, 30 days, only bots that person may open) for reading away from home
    • Android app (app/src-tauri, Tauri 2): Gate only, the server isn't built for Android. Loads the Farm's page over the pinned link; window.oxbotGate.socket() stands in for the WebSocket over Tauri channels; 15 s heartbeat; QR read on the phone with rqrr (no Google services); pairing saved in farm.json, backups off
    • Per person: approval cards go only to their asker and the Farm; each person has a private Herder (assistant--<slug>-<hash>) with the Farm Herder's instructions and model, shown to them as assistant. A message line starting with [ gets a backslash, so nobody can fake a [Name] sender

  19. M2.11

    One shared browser, sign in once, who sent each message 2026-10-29

    • Jay's call: sign in once and every bot stays signed in. One Chrome for all bots, kept profile at <data folder>/browser/profile, hidden (--headless=new); it turns into a normal window only while you sign in, on the same control port (127.0.0.1 only)
    • Chrome quits with the DevTools Browser.close command so new cookies are saved (SIGTERM only as a fallback). Settings → Sign out of all sites deletes the profile. Downloads go to the folder of the bot using the browser
    • Bots take turns: a bot takes the browser at its first browser action and keeps it until its reply ends; others wait ("Waiting for the browser (X is using it)…"). When a different bot takes over, tabs reset to one blank page
    • Sign-in tool back, hosted inside oxbot: request_sign_in (oxbot-core::tools) is given to Claude Code as an sdk MCP server; its JSON-RPC rides the stream-json link (control_request mcp_message → control_response mcp_response). No helper process, no extra port
    • Sign-in flow: bot asks → sign-in card → Open sign-in window → shared Chrome restarts visible on that page → you sign in yourself → I'm signed in (or close the window) → hidden again, the bot reloads and carries on. 10-minute timeout
    • Safety rules for a signed-in browser: reading, opening pages, scrolling and typing run; clicking Send, Post, Reply, Delete, Buy, Submit, Confirm, Save, Share… or Enter in a text box (not a search box) shows a red card with a screenshot; uploads show an amber card; password, code and card-number fields refused (the bot is told to call request_sign_in); scripts in pages (evaluate_script), non-web URLs, files outside the bot folder and unknown tools refused
    • The guard (oxbot's own DevTools connection, read-only Runtime.evaluate) reads the page to tell password fields, search boxes and what's under a click_at point
